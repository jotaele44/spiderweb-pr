# PR DEM Follow-Up Packet Workflow

This workflow generates per-candidate follow-up packets for reviewed and routed PR DEM candidates.

Tool:

```text
tools/pr_dem_follow_up_packet_generator.py
```

Context checklist:

```text
configs/pr_dem_follow_up_context_layers.json
```

Default input queue directory:

```text
outputs/pr_dem_review_queues/
```

Default output directory:

```text
outputs/pr_dem_follow_up_packets/
```

## Inputs

The default packet run uses:

```text
outputs/pr_dem_review_queues/queue_escalated.geojson
outputs/pr_dem_review_queues/queue_retained.geojson
```

These are generated by:

```text
tools/pr_dem_review_decision_router.py
```

## Outputs

| Output | Purpose |
|---|---|
| `briefs/*.md` | One markdown brief per candidate |
| `follow_up_index.csv` | Spreadsheet-friendly packet index |
| `follow_up_index.json` | Machine-readable packet index |
| `follow_up_packet_summary.md` | Human-readable summary |
| `follow_up_manifest.json` | Input/output checksum manifest |

## Packet contents

Each packet contains:

| Section | Purpose |
|---|---|
| Status | Queue, score, review decision, confidence, next step |
| Coordinates | Lon/lat and/or projected coordinate fallback |
| Terrain / context summary | Slope, area, TPI, terrain visual type, access/hydro/utility/karst/imagery context |
| Review notes | Human review notes from the locked review layer |
| Context-layer checklist | Standard follow-up checks |
| Analyst disposition | Final disposition checklist for next manual pass |
| Guardrail | Reminder that the packet is not a confirmation |

## Context-layer checklist

The context checklist includes:

| Layer | Purpose |
|---|---|
| DEM hillshade | Check terrain expression and raster artifacts |
| Slope raster | Check internal flatness and surrounding contrast |
| Recent imagery | Check visible clearing, structure, obstruction, or no signal |
| Historical imagery | Check appearance, disappearance, expansion, or stability |
| Roads / TIGER edges | Check access context |
| Hydro / water assets | Check stream, reservoir, drainage, or water-utility context |
| Power / utility layers | Check utility corridor or facility context |
| Karst / geology | Check karst/interface/depression context |
| Parcels / ownership | Check ordinary land-use explanation where available |
| False-positive check | Check quarry, road cut, pasture, natural summit, building pad, or data artifact |

## Command block for later

Default escalated + retained packet generation:

```bash
python tools/pr_dem_follow_up_packet_generator.py \
  --queue-dir outputs/pr_dem_review_queues \
  --context-config configs/pr_dem_follow_up_context_layers.json \
  --output-dir outputs/pr_dem_follow_up_packets
```

Escalated-only packet generation:

```bash
python tools/pr_dem_follow_up_packet_generator.py \
  --queue-dir outputs/pr_dem_review_queues \
  --include-queue escalated \
  --context-config configs/pr_dem_follow_up_context_layers.json \
  --output-dir outputs/pr_dem_follow_up_packets_escalated
```

Packet test run capped to 10 candidates:

```bash
python tools/pr_dem_follow_up_packet_generator.py \
  --queue-dir outputs/pr_dem_review_queues \
  --context-config configs/pr_dem_follow_up_context_layers.json \
  --output-dir outputs/pr_dem_follow_up_packets_test \
  --max-packets 10
```

## Follow-up packet gate

Do not treat the packet stage as complete unless:

1. `follow_up_index.csv` exists and is non-empty.
2. `follow_up_packet_summary.md` exists and is readable.
3. `follow_up_manifest.json` contains input/output checksums.
4. At least one `briefs/*.md` file exists when the selected queues contain candidates.
5. The packet count matches the expected escalated/retained queue count.

## Guardrail

Follow-up packets are review-management artifacts only. They do not confirm infrastructure, hidden infrastructure, or subsurface activity. They organize cross-layer validation work.
